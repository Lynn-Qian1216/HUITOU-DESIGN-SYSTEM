# HUITOU AI 设计系统

## 在 Codex 中运行与迭代控制台

本目录也是慧投控制台的可交互源码项目。首次运行 `npm install`，之后执行 `npm run dev`，打开 http://127.0.0.1:5173 。Windows 下也可以双击根目录的 `启动慧投.cmd`。

- 正式预览入口：`ui_kits/console/index.html`；登录页可不填手机号，直接点击「登录」进入演示。
- 可视化设计系统：http://127.0.0.1:5173/design-system/ ，可浏览规范、搜索设计变量与操作组件示例。
- 页面与业务交互：`ui_kits/console/*.jsx`。修改后刷新浏览器即可，不需要重新导出画板。
- 控制台内部页面使用原始设计系统样式；登录页独立使用 `auth.css`，保留苹果风设计和银白柔光背景。
- 基础组件：`components/`；页面当前加载的组件运行包：`_ds_bundle.js`。修改基础组件时需要同步运行包，单独修改组件源文件不会自动更新运行包。
- 颜色、字号和间距：`tokens/`；全局样式：`styles.css`；品牌素材：`assets/`。
- `figma-*`、`prepare-figma-*` 和 `_figma/` 是之前还原设计稿的辅助文件，不是交互项目入口。

这是用于页面设计与流程验证的前端原型：账户数据、AI 回复、登录及投放操作使用演示逻辑，未连接真实业务后端。React 与 Babel 已使用本地安装的固定版本；字体仍使用 `tokens/fonts.css` 中的在线字体和系统回退字体。

默认开发服务只监听本机。退出终端后需要重新运行 `npm run dev`。后续在 Codex 中直接描述要修改的页面、交互或设计即可继续在本目录迭代。

HUITOU AI 是一套 AI 驱动的广告投放操作系统，为每个广告账户配备专属 AI 投手：读取数据、诊断问题、提出策略、自动执行变更，并从结果中学习。四阶段闭环 —— **诊断 → 制定策略 → 自动执行 → 持续学习** —— 是界面与官网共同的组织逻辑。

整套系统以单色为主。黑、白与冷调石板灰承担结构与层级；颜色只用在有明确含义的地方：状态、通知、链接、数据序列，以及单一主操作。气质是智能、冷静、精确、专业：充足留白、极细描边、柔和圆角、清晰层级。不用装饰性渐变、厚重阴影或活泼装饰。

**替代方案（待确认）：** 未提供品牌字体与图标库。字体用 Google Fonts 的思源宋体 / 思源黑体 / Geist / Geist Mono，声明集中在 `tokens/fonts.css`；图标用 [Lucide](https://lucide.dev)，封装在 `Icon` 组件里。两者都是一处替换、全局生效。国内访问 Google Fonts 不稳定，上线前建议换国内 CDN 或本地子集化。

# 内容规范

**语气：冷静的分析者。** 文案像一位资深投手在会议间隙向你简报 —— 工作已经做完，他告诉你发现了什么、接下来打算怎么做。笃定、具体，不夸张、不推销。

**人称。** 称用户为**你**。产品以第三人称称呼自己（「HUITOU 暂停了 3 个广告组」「你的 AI 投手发现……」），不用「我」。应用内避免「我们」，那留给官网与法务文本。

**大小写与标点。** 英文一律句首大写。中文短标签不加句号，正文用全角标点。界面名称（诊断、策略、自动驾驶）视作专有名词。全大写仅用于 `--type-overline` 眉标与坐标轴标签。

**数字承担论证。** 每个判断都挂上数字和时间窗口：「CPA 较前 7 天下降 18%」优于「效果有所提升」，永远写明对比基准。金额超 1,000 取整，低于 1,000 保留两位小数；百分比只在小于 10% 时保留一位小数。

**机器动作是回执，不是庆祝。** `已暂停「再营销 — DTC」· 预计每周节省 ¥412 · ROAS 连续 5 天偏低 · 14:02`。不用感叹号，不写「干得漂亮！」。

**不确定性要说出来。** 置信度与证据是一等文案：「高置信度 · 21 天数据」「转化量不足，还需 30 次才能下结论」。产品可以承认自己不知道。

**错误信息中性且可执行。** 先说发生了什么，再说怎么办：「Meta 授权已过期。重新连接后可恢复自动变更。」不指责，不重复道歉。

**不使用表情符号。** 状态由色点、徽标或图标承担。

| 推荐 | 不推荐 |
|---|---|
| `4 个广告系列的 CPA 高出目标 34%` | `糟糕 —— 你的 CPA 飙得有点离谱 😬` |
| `应用策略` | `一键起飞！` |
| `该广告组数据不足，暂时无法诊断` | `出错了` |
| `HUITOU 已将每日 ¥1,200 转向「拉新 — 美国」` | `我们已为你优化预算，助力业绩腾飞` |

**官网标题**用陈述短句（中文 8–16 字）配一行具体副标题：*「每个广告账户，都有 AI 投手。」/「HUITOU 持续读取账户数据，找出预算漏损、执行修复。」* 不用疑问句，不用「重磅推出」。

# 视觉基础

## 色彩

单色优先。一屏界面在灰度下也应当层级正确；颜色只用于编码含义。

- **中性色**为冷调石板灰 11 级（`--neutral-0` → `--neutral-950`，最深 `#1B2126`）。深色只用于文字、主按钮填充与反色区块，从不用作描边。页面底色 `--neutral-50`，卡片纯白，因此不靠阴影也能分层。
- **语义强调色** —— 蓝 `#1D5BD6`（链接、信息、AI 选中态）、绿 `#0A886C`（成功、正向）、琥珀 `#A57314`（警告、待复核）、红 `#C22D3B`（错误、负向、破坏性）、紫 `#5A50CD`（**仅用于 AI／自动化**）。
- **用色预算：** 单张卡片最多一种强调色，一屏不超过三种（数据序列与行内状态点不计）。
- **主操作是黑色**（`--action-primary-bg: var(--neutral-900)`），蓝色是链接色不是按钮色。
- **数据可视化**以墨色与灰色为主，只在序列需要区分身份时用色相。正负变化恒用绿／红，不能只靠箭头方向。

## 字体排印

**超大标题用思源宋体 Heavy 900**（`--font-display`）—— 官网首屏主标题、38px 区块标题、48px 数据字，宋体的粗横细竖在大字号下提供份量。其余一切用**思源黑体**，西文与数字用 Geist，表格数字／ID／时间戳用 Geist Mono。黑体层级靠字重区分：正文 400、小标题与标签 500、表头 600。宋体只用 900 一档，不用于 20px 以下。

字号刻度 11 / 12 / 13 / 14 / 16 / 18 / 20 / 24 / 30 / 38 / 48 / 56 —— **只能取刻度内的值**，需要区分层级就换字重或换相邻档，不要新造 token。中文正文行高 1.65，黑体标题 1.25，宋体大标题 1.18–1.3。正文宽度上限 `--layout-max-prose`（68ch）。

控制台的实际用字比网页紧：**正文上限 13–14px，最常用 12px，次级 11px**。表格与指标中的数字一律 `tabular-nums`，保证列对齐、刷新时不跳动。

## 间距与布局

以 4px 为基数，刻度为 2、4、6、8、12、16、20、24、32、40、48、64、80、96、128。卡片内边距 20px（`--gutter-card`），区块与页面 32px。控件只有三种高度：28 / 34 / 40px。官网内容居中，最大宽度 1160px。

留白是首要的结构手段。版面拥挤时删掉一个元素，而不是压缩间距。

## 描边、圆角与层级

**层级由描边承担，阴影几乎不存在。** 几乎每个表面都由 1px `--border-subtle` 界定。卡片为白底、1px `#E2E7EB` 描边、10px 圆角，静止无阴影。圆角：4（标签）、6（控件，默认）、8、10（卡片）、14（面板、弹窗）、20（官网大区块）、胶囊（徽标、头像、开关）。

阴影只服务浮起层：`--shadow-sm` 悬停卡片、`--shadow-md` 浮层与下拉、`--shadow-overlay` 弹窗。不用彩色阴影。遮罩 `rgba(16,20,24,.44)`；模糊（`--blur-scrim`）**只用于分层**，绝不作装饰。其余用到透明度的只有禁用态（.45）与骨架屏。

**不使用渐变。** 唯一例外是滚动溢出边缘的淡出保护渐变，颜色与所在表面相同。

## 交互状态

- **悬停：** 背景下沉一级（`--surface-hover`）；链接加深至 `--blue-700` 并加下划线。描边最深只到 `--border-default` —— 任何交互态都不出现接近黑色的描边。
- **按下：** 背景再下沉一级。不做缩放 —— 界面不弹跳。
- **聚焦：** 输入控件不加焦点环，只把最外层描边加深到 `--border-strong`。不用浏览器默认轮廓，不用彩色光晕。
- **选中：** 填充 `--surface-selected`；导航项左侧 2px 黑色指示条，卡片用 1px `--border-focus`。
- **禁用：** `--surface-disabled`、`--text-disabled`、`cursor: not-allowed`，不对整个容器降透明度。
- **滚动条：** 全局统一，滑块 6px 宽、完整胶囊（3px 透明边框 + `background-clip: padding-box`）、轨道透明，规则在 `tokens/base.css` 全局声明。隐藏某容器的原生滚动条加 `.huitou-noscrollbar`。**不要声明 `scrollbar-width`** —— Chrome 121+ 一旦看到它就改用标准渲染，整套自定义失效。
- **行内编辑：** 可编辑值默认只显示数值，行悬停时才淡入铅笔按钮。按钮始终占位、只切透明度，避免列宽跳动。
- **卡片悬停：** 整卡可点的卡片微微抬起 —— 放大 `1.006` + `--shadow-md` + 描边加深，140ms。幅度必须小：队列里卡片紧挨着，放大多了会顶得相邻卡片晃。
- **表格行悬停：** 所有列表每一行都要有反馈，背景下沉到 `--surface-hover`；选中行保住自己的底色。统一用 `TableRowHover`。
- **加载：** `--neutral-100` 骨架块，1.4s 呼吸。2 秒以内用旋转指示器，更长的一律用带文字说明的确定性进度条。

## 动效

快、克制、不炫技。`--duration-fast`（120ms）悬停与按下，`--duration-normal`（180ms）浮层与下拉，`--duration-slow`（280ms）抽屉与弹窗，`--duration-deliberate`（420ms）只用于智能体动态流的新步骤展开。

**面板与子页面统一 250ms。** 侧栏与数据面板的展开／收起是**宽度过渡**，内容层锁定最终宽度，动画期间不重排 —— 逐帧重排是卡顿的来源。拖动分隔条与切换侧栏期间**临时关闭过渡**让面板跟手。缓动 `cubic-bezier(.2,0,0,1)`。只做淡入淡出与 4–8px 位移，不弹跳、不旋转、不视差。`prefers-reduced-motion` 下全部归零。

窄窗自动收起侧栏用**双阈值**（收起看 1000px、恢复看 1180px）：收起只省下 172px，单阈值会让侧栏在边界宽度上无限抖。测宽的 `ResizeObserver` 回调必须 `requestAnimationFrame` 合帧、只在跨阈值时写 state。

## 应用外壳

控制台是对话优先的三段式布局，详见「控制台外壳」卡片：

| 部件 | 尺寸 | 说明 |
|---|---|---|
| 顶栏 | 高 56px，灰底 | 标识 + 「工作台 / 广告投放」分段控件 + 通知铃 |
| 内容面 | 白底，左上／右上 20px 圆角 | 三面细描边 |
| 会话侧栏 | 228px，可收起至 56px | 账户切换、新对话、投放设置、历史对话、底部用户 |
| 分隔条 | 9px，可拖动 | 会话区占比 22%–72%，双击复位 46% |
| 数据面板 | 剩余宽度，最小 300px | 右侧图标栏点开的分析界面 |
| 图标栏 | 64px，白底 | **随账户所属平台变**，未读加红点 |

**缩略侧栏（56px）保留四项常驻入口**：账户切换、新对话、投放设置、底部用户 —— 收起不是消失，这四件事任何时候都要能点到。图标与展开态保持一致，不换字形也不换配色。

**侧栏级页面**（投放设置）会同时替换会话区与数据面板并隐藏图标栏 —— 它不属于某个账户，回到会话靠左栏的「新对话」或历史对话。

## 智能体回复

回复不是一段文字，而是**可组合的区块序列**，逐块生成（每块 700ms）：

`text` 结论 → `section` 带小标题的说明段 → `inquiry` 询问卡（缺条件时向你要参数）→ `metrics` 紧凑指标卡 → `chart` 双轴图 → `table` 紧凑表格 → `decision` 决策卡 → `footnote` 来源与操作。

两条内容约束：**图表和表格前后必须有文字解读**，写图里看不出来的判断（「消耗爬升但 CPA 走低，说明买到的是更便宜的流量」），不复述数字；**结尾给下一步与回滚条件**，不要以数据结束。

**生成过程分四段**，每段回答一个不同的问题（详见「对话框」笔记）：起手只有 `AgentLoading` 的奔跑猫 + 骨架屏；首块内容落地后顶部出现「正在回复 12 秒」；生成中猫跟在内容尾部、文案换成当前这一步的实际工作（「报表管家 读取投放数据」）；收口后变成「用时 1 分 04 秒」+ 可展开的工作明细。等待不是需要被掩盖的空白，而是唯一能展示 AI 在做什么的窗口。

## 状态与业务词汇

同一状态在任何界面必须用同一色调与同一措辞，见「业务状态枚举」卡片：

- **决策** 当前队列：待执行（琥珀）· 验证中（绿，呼吸点）· 失败（红）· 已拒绝（中性）；历史：已执行（绿）· 已失效（中性）。每条带三轮验证进度（`RoundsProgress`）与「预计影响」金额。
- **达人分销** 四节点：申请合作 → 商品授权 → 建广告 → 投放中（`ProgressTrack`）。批次内按 完成 / 失败 / 暂停 / 进行中 / 未开始 五档计数。
- **授权** 授权生效 · 待达人确认 · 授权失败 · 未申请。
- **健康度** 优秀 ≥90（绿）· 良好 ≥75（琥珀）· 合格 <75（中性），用 `ScoreRing`。
- **令牌** 令牌有效（次级按钮）/ 激活令牌（红色按钮）—— 状态即操作，不另设状态列。

措辞取「已执行」「待执行」这类完成体，不用「执行成功」「等待中」；金额带 ¥ 与千分位，比率带 %。

### 决策卡片的状态

同一张卡，各状态换的是**内容重点和出口**，不是换配色皮肤：

| 状态 | 三级内容 | 主操作 |
| --- | --- | --- |
| 待执行 | 目标一行 | 执行 / 拒绝，带失效倒计时 |
| 验证中 | 指标进度（起点 → 最新值 · 目标 · 三轮圆点） | 验证中…（禁用）/ 立即回滚 |
| 失败 | 失败原因 + 指标进度 | 调整后重试 / 不再尝试 |
| 已拒绝 | 目标一行 | 恢复执行；改动值划掉压灰 |
| 已执行 | 指标进度走完三轮 | —；收益标「实际影响」 |
| 已失效 | 目标一行 | —；一轮没跑，不显示进度 |

- **只有真正拿到结果的收益才是绿的。** 回滚、过期、被拒都属于「这笔收益没发生」，显示成绿色等于谎报战果；标签也要从「预计影响」换成「实际影响」或「原预计影响」。
- **达标与否由目标本身推导**（取「≥」「≤」与数值比较），不靠数据里手写的标记 —— 漏写一次，界面就会把没达标的数说成达标。
- **验证一旦开始，「当初想干什么」就不如「现在到了什么数」重要** —— 所以验证中与失败把目标换成指标进度，最新值直接按目标着色。
- 失败是终态，措辞要写死（「验证终止 · 2/3 轮」），按轮数推会说成「验证中 · 第 3/3 轮」，与「验证提前终止」自相矛盾。
- 失败的主操作是「调整后重试」，不是原封不动再跑一遍。验证中必须留「立即回滚」：数不对时人得能立刻停手。
- 待执行与已拒绝**不显示三轮进度**：一轮都没跑，空进度条只是噪音。任何终态都不再给「修改数值」的铅笔。
- 不用左侧色条区分状态 —— 一列卡片挂五条彩带只剩噪音，状态靠描边轻重、页脚底色和角标传达。

## 多平台

一个工作区里同时接着巨量千川与腾讯营销的账户。两个平台的投放对象不是一套东西 —— 千川围绕商品与达人带货，腾讯营销围绕创意组件与人群包。

- **导航随账户走。** 切账户即切平台，右侧图标栏整组换掉。不做「一套导航 + 灰掉不支持的项」：灰掉的入口只会让人反复去点。
- **平台在切换器里是并列入口**，不是列表里的分节标题 —— 一个平台上百个账户时，顺序铺开会让第二个平台永远在滚动条尽头。用平台标签页 + 品牌标（`PlatformMark`），标签上带各平台的账户数（搜索时两个平台都计数）。
- **账号标签**：用户给账户起的名字（一个，不是多个标签），在列表里就地编辑。切换器主行显示它，平台方的原名与 ID 降到 11px 副行 —— 平台名由品牌标承担，不再占一行文字。
- 共有的三块（账户概览 / AI决策 / 广告投放）复用同一套界面，只换指标：千川看 GMV、ROI、达人；腾讯看曝光、点击率、转化成本、版位。
- 切平台时收起数据面板，不保留上一个平台的页签 —— 「创意」在千川不存在，留着只会打开一个空面板。

### 腾讯营销的四块

- **创意** —— 列表按**疲劳度分组**（已疲劳排最前），CTR 旁给出较首周的跌幅，让人看出这个判断是怎么来的。素材拆解把文案 / 形式 / 版位各自汇总（一条创意跑得差，可能是文案不行也可能是封面不行，只看整条分不出来）；组合测试用二维矩阵看「同一文案 × 不同封面」。
- **组件** —— 创意组件 / 落地页组件 / 落地载体分三个标签页。三者是三种东西，放同一张表会让「引用数」失去意义。引用数为 0 的是死库存，压灰让人一眼看出该清理；组件未过审会让引用它的整条创意一起投不出去，要写在提示里。
- **人群包** —— 新鲜度按「距上次更新天数 / 该来源的建议更新周期」算：同样 7 天没更新，行为人群包已经过期，基础属性包还很新。所以给条 + 天数（「7 天前更新 · 建议 7 天」）。失效提醒写后果 ——「已过期」不说明问题，「腾讯侧不再放量，预算会挤到其余人群包里」才说明问题。
- **投放矩阵** —— 批量建计划的**配置台**，不是报表。两轴交叉出的每格是一条计划；提交前把名字、预算、出价摊成清单，因为批量建错的代价是几十条计划同时跑错。不可投的项**照常可勾选**，只标出原因 —— 禁用掉等于替人做了决定，而人常常是先勾上想投的、再回头处理那几个。拦截发生在提交时。

## 会话滚动与输入

对话流的滚动锚点是**本轮提问**，不是列表末尾 —— 用户要从回复开头看起。

- **发送后把本轮提问滚到接近顶部**，上方保留 144px 上文，读起来是同一段对话的延续。
- **列表末尾插入占位空白**，新提问才有空间被顶上去；回复逐块向下长进这块空白，生成期间视口不动。生成结束后仍保留半屏留白 —— 既给滚动空间，也是收口信号，最后一行贴着输入框会被读成「还没写完」。
- **上移用 `scrollTo({ behavior: 'smooth' })`**；占位与骨架的高度是异步长出来的，80ms 后再校一次目标位。载入历史对话直接贴底，不做动画。
- **新一轮提问上方比轮内多一档间距** —— 一问一答是一个语义单元，同间距会让长会话失去可扫读的节奏。
- **发出的消息悬停时给复制与编辑重发**。复制含引用；编辑重发把原文与当时的引用一起回填。操作条占固定高度 —— 高度随悬停变化会让会话在鼠标移动时跳动。
- **滚动条按需出现**：鼠标进入会话区时出现，离开隐藏，悬停加粗。

### 附件

- 三条入口：点回形针、拖进输入框、直接粘贴剪贴板里的图。拖拽时输入框内浮一层虚线提示并写明上限。
- 附件与 @ 引用**分两行**：一个是「我带了什么文件」，一个是「我在问哪个对象」，混在一排里胶囊长得又像，扫一眼分不出。附件在上，离回形针近。
- 用 `FileCard`（带缩略图），不用 `FileChip`。图片当场生成本地预览地址，不等上传回链接。校验在客户端就做，当场落到失败态。

### @ 引用

素材上千条、商品数百条，平铺长列表是找不到东西的。面板分两层：

- **不输入时**给「最近引用」+ 六个类型入口（各带条数）。绝大多数提问都在重复引用同几个对象，一次点击就完事。
- 面板顶部的搜索框与正文里 `@` 后面的字是**同一份内容**，在哪边打都行；打开即聚焦。
- **一输入就跨类型搜**，每组只露前 4 条，后面接「在商品中查看全部 482 条」收进单类。**进入单类后**顶部挂范围胶囊，Backspace 或 Esc 退出。
- **面板高度写死。** 它向上展开，内容一多一少就改高度的话顶边会上下窜，点进一类再返回列表整个错位。宁可留白也要待在原地。
- 只有词首的 `@` 触发（前面是空白或行首），邮箱里的 `@` 不弹面板。每行右侧给一句现状（`投放中 · 日耗 ¥12,480`），同名对象靠它区分。
- ↑↓ 选、Enter 插入、Esc 关。**面板开着时 Enter 归插入用，不发送** —— 否则选引用会顺手把半句话发出去。
- 插入后把 `@` 及查询词从草稿里抹掉，引用落成输入框上方的胶囊。正文里不留 `@字符串`：改一句话时误删引用是这类输入框最常见的坑。
- **引用随消息一起发出**，留在气泡正文上方 —— 「这条计划为什么起不了量」本身没有主语，引用不进消息，历史里就只剩一句无主语的问话。
- 不用 `scrollIntoView` —— 它会连带滚动外层容器，破坏面板布局。写目标容器的 `scrollTop`。

## 列表页布局

四处列表（广告投放、商品库、达人、账单）共用一套结构：

- **单层纵向滚动。** 页面交给外层滚动容器，**不要嵌套滚动区** —— 面板变窄时内层 flex 会被压成几十像素，列表整段不可见。
- **用 `TableFrame` + `StickyFooter`**（或简写 `ListShell`），不要各页自己搭。宽表**两侧都冻结**：左侧勾选框、开关与名称，右侧操作列。只冻结左侧会让人滚到最右操作、再滚回来确认改的是哪条。
- **遮挡用渐变，不用阴影。** 冻结列与滚动区交界处的渐变覆盖层随滚动位置淡入淡出，同时充当横向位置提示。阴影落在单元格上会给每行加一道暗边，行的分界线变成两条。
- **翻页条吸底**（`position: sticky`，`bottom` 取所在容器 `padding-bottom` 的负值，运行时量取），含「共 N 行 · 每页 N 条 · 第 X / Y 页 · ‹ ›」。横向滚动轨长在翻页条顶部，与表格 `scrollLeft` 双向同步，表格不溢出时不出现。
- **sticky 的两个陷阱**：带 `transform` 的祖先与 `overflow: hidden` 的容器都会让它失效。吸底元素必须是滚动区的直系后代；宽表不要放进 `Card`（默认 `overflow: hidden`，需要时传 `overflow="visible"`）；入场动画结束后把 `transform` 置 `none` 而非 `translateX(0)`。
- **单行不换行。** 名称、标签、来源都用省略号截断，完整文本走 `title`。省略方向要挑：账户 ID 从前面截（前缀相同，尾号才是区分位），文本从后面截。
- **汇总数字由明细推导**（`reduce` 求和／计数），不要与列表各写一份常量。汇总卡宽屏四列、窄屏最少三列 —— 降到两列时卡片会宽到数字与标签之间出现大片空白。
- **空状态区分成因。** 「没有匹配的结果」与「还没有接入」用不同文案与图标：一个放宽条件，一个去接入。一句「暂无数据」会把人推向错误的下一步。

## 说明文字

**解释性副文都收进标题旁的问号**（`InfoHint`），悬停展开。判断标准是「这行字会变吗」—— 会变的是信息（倒计时、计费周期、数据时效），留下；不变的是解释，收起。空状态的说明与表单字段的 hint 例外：前者本身就是那块区域的全部内容，后者填写时要和规则同时看见。

气泡用 `position: fixed` 自测位置并夹回视口内 —— 卡片带 `overflow: hidden`、内容区带 `overflow: auto`，绝对定位的气泡贴着容器边缘会被裁掉半句话，半句解释比不给解释更糟。`Tooltip`、`AnchoredPanel`、`DropdownMenu` 同理。

## 图像

品牌不依赖摄影。需要视觉元素时用的是**产品本身**：真实的表格、图表、智能体日志，套在浏览器或面板外框里。若必须用照片，取低饱和、冷调、高亮度、留白充足的画面。未确立插画风格，也不应在没有方向时自行发明。不用重复图案或纹理；唯一的背景处理是官网首屏后方极低密度的 1px 点阵。

# 图标规范

- **尺寸：** 正文内联 14px，控件与导航 16px，空状态与区块标题 20px，最大 24px。任何尺寸下描边都保持 1.5px —— 不要随尺寸缩放描边。
- **颜色：** 继承 `currentColor`，绝大多数为 `--text-secondary`；只有相邻文字使用强调色时才跟随。
- **禁止**填充、双色调，禁止放进彩色圆形底片。标签已表达含义时，优先用 8px 状态点而非状态图标。
- **表情符号绝不作为图标。** Unicode 只用作排印符号 —— `·` 分隔元信息，`→` 用于行内链接，`↑ ↓` 出现在变化率旁。
- **猫形图标**是唯一的品牌图形，在应用左上角以 20–32px 使用，绝不改色、旋转、描边或置于杂乱背景上。最小安全边距等于猫耳高度。
- **平台品牌标**（千川、腾讯营销）是例外的多色资产，只用在「这一行属于哪个平台」的位置，统一走 `PlatformMark`，不加彩色底片。

`assets/` 中：`logo-wordmark.svg`（原始）、`-current.svg`（继承 `currentColor`）、`-inverse.svg`（白色），以及对应的三个 `logo-mark-*.svg`（纯图标 32×32）。

### 几个组件存在的理由

- `Icon` —— 对 Lucide 的封装层，日后换图标库只需改一个文件。
- `AgentTimeline` —— 四阶段闭环的动态日志，几乎出现在每一屏，交给各方各自实现必然走样。
- `TableFrame` / `StickyFooter` / `ListShell` —— 长列表页的固定结构（双侧冻结 + 遮挡渐变 + 吸底翻页条 + 自动出现的横向滚动轨）。它解决的是 sticky 与嵌套滚动的坑，不该每页重新踩。
- `AgentInquiry` —— 智能体缺条件时向你要参数的询问卡。选项即答案，选完直接重新派单；未选满主操作禁用，另给一条「用默认范围」的出口。等待期间界面上不出现任何数据或结论 —— 空跑的数字比没有数字更糟。
- `FileCard` / `FileChip` —— 附件的两档形态。图片给真缩略图：一次传五张截图，光看 `image.png` 谁也认不出哪张。`FileChip` 三种状态共用一个外形只换右侧一小块 —— 换形状会让同一批文件在上传过程中排版反复重排；文件名从**中间**截断，尾部的 `_final_v3.mp4` 才是分辨两个文件的地方。
- `PromptQueue` —— AI 生成时不锁输入框，新提问排队、本轮结束后依次发出。生成中的发送按钮换成 `list-plus` + 次级底色 —— 不换的话，点下去像是要打断当前回答。
- `MentionChip` —— 提问时引用的对象。胶囊必须分两段：类型 + 名字 —— 只写名字的话「藤椒味」既可能是商品也可能是素材。智能体走紫，其余一律中性：一排胶囊里五种颜色等于没有颜色。
- `AnchoredPanel` —— 浮层底座，下拉、日历、筛选面板都走它。**不要用 `position: absolute` 自己摆浮层** —— 列表页的卡片和滚动容器都带 `overflow: hidden`，这是下拉「被遮挡」的唯一原因。它用 `fixed`，量完位置再显示，外点与 Esc 关闭也收在里面。
- `InfoHint` —— 说明文字的收纳位。
- `FilterBar` / `FilterSelect` —— 筛选控件与其容器。**标了计数就必须真的筛** —— 选项上写着 12 条、选完表格没动，比不给计数更糟；命中 0 的项置灰保留而不移除，选项列表随数据增删会让人以为自己看错了。
- `DateField` / `DateRangeField` / `TimeRangeField` —— 区间选择**反着点自动调头**而不是弹错误，未落笔的一半跟着鼠标预览，底部要一次「确定」以免选到一半就触发查询；时间按 `minuteStep` 取值（投放时段只落在整点或半点，逐分钟要滚 60 行）。数字一律 `tabular-nums`，切换区间时同排筛选控件才不会跟着抖。
- `RoundsProgress` —— n 段短条 + 「验证中 · 第 2/3 轮」。不用点阵，三个小圆点谁也读不出第几轮。
- `TableRowHover` —— 行悬停的 props 工厂（`{...TableRowHover(base, locked)}`）。写成工厂而非组件，因为 `<tr>` 常带各页自己的 style / onClick。
- `DecisionCard` 与整个 decision 分组 —— 同一条决策要在队列卡、详情页、历史列表三处出现，级别方章、时效胶囊、指标进度散在三处手写必然各写各的颜色。
- `AgentLoading` —— 等 AI 出结果的地方都用它（逐帧奔跑猫 + 状态文案 + 与回复同形的骨架）；`Spinner` 只留给保存、刷新这类非 AI 的短操作。
